## Architecture and Testing Standards

These standards apply to every final code/configuration change in this plan. Presentation and documentation-only tasks do not require product tests unless they alter code or test/CI wiring.

- Keep final code aligned with the feature-first structure: client features under `client/src/features/<feature>/`, backend features under `server/src/features/<feature>/`, and only cross-feature reusable primitives/adapters under each app's `src/shared/`.
- Keep login and registration separate under `client/src/features/auth/login/` and `client/src/features/auth/registration/`. Maintain clear feature interfaces and separation among presentation, domain logic, API transport, and persistence.
- Every final behavior/configuration change adds or updates unit tests, integration tests at affected API/database/auth/provider boundaries, and E2E regression tests for impacted supported user journeys. Re-run the complete critical-flow suite against the release candidate.
- Unit tests stay with their feature; integration tests live in `client/tests/integration/` or `server/tests/integration/`; end-to-end regression tests live in `tests/e2e/`. Test data and demo accounts remain fictional.
- S5-03 publishes the actual results for all three test layers; S5-04 and S5-06 rehearse the same E2E flows and fallback paths against the release candidate.
